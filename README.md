# AlfaHack — персональная бизнес-аналитика

Решение кейса Альфа-Банка «Новостная аналитика для принятия бизнес-решений» на базе BrandRadar. Пользователь выбирает компанию и роль, чтобы получить значимые события, объяснение влияния, риски/возможности и проверяемые источники.

**Статус:** полностью перенесена исходная кодовая база BrandRadar; адаптация под кейс ещё не реализована. Существующая логика — мониторинг брендов и тональности. Полный запуск перенесённого приложения в текущей среде не подтверждён; ограничения перечислены в [отчёте переноса](docs/migration-report.md).

## Структура

```text
backend/               Go / Gin: существующие API, SQL, сбор, фоновые обработчики
frontend/              React / TypeScript / Vite: лента, карточки, фильтры, UI
ml/                    Python / FastAPI: существующие модели брендов; зона нового поиска и LLM
contracts/             Согласуемые схемы нового решения
docs/                  Продукт, архитектура, роли, адаптация и отчёт переноса
docker-compose.yml     Исходный full-stack Compose BrandRadar
```

Сохраняем Go backend и React. Новый Python-компонент отвечает за retrieval и LLM; единственный владелец состояния задания и переходов — Go backend. Персонализация, аналитика банка, доказательства и собственный агентный цикл добавляются командой.

## Начать работу

1. Прочитать [ТЗ](docs/requirements.md), [продукт](docs/product.md), [архитектуру](docs/architecture.md), [план адаптации](docs/adaptation.md).
2. Найти себя в [плане команды](docs/team.md), прочитать свой файл в [docs/agents](docs/agents/) и AGENTS.md.
3. Согласовать контракт с владельцем API; работать в личной ветке, общий код менять отдельным PR.

```sh
git clone https://github.com/DenisMekh/AlfaHack.git
cd AlfaHack
git switch -c feat/<role>-<task>
```

## Запуск унаследованного приложения

Исходная команда: `docker compose up --build`. **Это запуск BrandRadar, а не готового решения кейса.** Текущий ML-сервис требует веса трёх старых моделей в MinIO; загрузки артефактов в пустое хранилище Compose не выполняет. Go требует 1.26.1 по go.mod; frontend Dockerfile использует Bun и bun.lock. Конфликты peer-зависимостей npm и ограничения сборки перечислены в отчёте. До исправления этих вопросов запуск не обещаем.

Конфигурация существующего backend описана в [backend/README.md](backend/README.md) и `backend/.env.example`. Корневая `.env.example` — **планируемая** конфигурация нового LLM-адаптера, текущий код её ещё не использует. Не запускайте старые модели как разрешённый AI кейса без проверки. Mock и режим API/local ещё предстоит реализовать.

Проверка полноты переноса без зависимостей:

```sh
python scripts/verify_upstream_import.py
```

Проверяет исходные байты на этапе baseline. После адаптации исходников различия ожидаемы; это не регрессионный тест продукта.

## Целевой сценарий сдачи

Две компании и две роли → разные приоритеты одного потока → карточка «факт / позиция банка / вывод AI» → источники → новая новость → самопроверка и, при необходимости, повтор поиска. Воспроизводимый Docker-запуск, синтетические данные, допустимая модель, фактические метрики, tag/commit SHA.
