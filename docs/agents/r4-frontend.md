## Владение

`frontend/`, UX notes и synthetic UI fixtures по согласованной схеме. Frontend Dockerfile/lockfiles координировать с Денисом. API schema — Роман Шваров. Не вычислять бизнес-ранг на клиенте.

## A1 — сценарий и первый экран

Добавить постоянный заметный вход на главной демонстрационной странице Альфа-Бизнеса; выбор компании/роли, персональную ленту и detail panel на общих fixtures. Отделять «Факт», «Позиция банка», «Вывод AI», «Нет данных»; показывать почему событие релевантно, возможные последствия/действия, даты и кликабельные источники с locator. Явно помечать mock и имитацию банковской интеграции.

Готовность: смена клиента/роли показывает согласованную выдачу; отдельные empty/loading/partial/error состояния; отсутствие аналитики банка видно. Доступность клавиатурой и читаемый русский текст.

## A2 — API runs

POST run → ограниченный polling GET статуса → карточки, ошибки и retry пользователя. Отменять/игнорировать устаревшие запросы при смене компании, включать company/role/period в ключи кэша, не показывать карточки прежней компании. Ссылки и текст безопасно рендерить.

Готовность: работа через настоящий Go API без спрятанной подмены fixtures, timeout/failed/partial различимы, feedback записывается. Удалить подстановки confidence=0.7 и relevant=true для неизвестных оценок — неизвестное показывается явно.

## A3 — воспроизводимая сборка и защита

Разобрать с Денисом Bun/npm и peer-конфликты Vite/plugin и date-fns/day-picker. Выбрать один поддерживаемый путь и обновить соответствующий lock отдельным PR. Проверять реальный TS project (`tsc -b` либо app tsconfig), а не считать пустой root `tsc --noEmit` достаточным. Пройти сценарий новой новости и смены клиента с командой.
