# R1 — Роман Аксенов: контекст компании, данные и помощь с инфраструктурой

## Что изучить

AGENTS.md, requirements, contracts, adaptation; `backend/internal/entity/brand.go`, `backend/internal/repo/pgrepo/`, `backend/migrations/`, `backend/internal/analytics/crawler/`. Brand хранит keywords и не является полноценным CompanyContext.

## Владение

Новые `backend/internal/company/`, entity/repo для компании и источников, SQL migrations, синтетические fixtures. Общие migrations/entity/repo менять с reviewer Романом Шваровым. Compose/CI — помощь Денису по отдельной задаче. Не менять ML/ranking или UI.

## A1 — словарь и профиль

Проверить реальные CSV, единицы, пропуски и неоднозначности; не коммитить сырьё. Описать mapping полей и ограничения. Согласовать CompanyContext schema с Романом Шваровым. Создать 3 синтетических клиента разной отрасли/продуктов, provenance каждого значения, `missing_fields`. Не получать рыночную долю из неполной выборки.

Готовность: воспроизводимый импорт, отчёт строк/ошибок/пропусков, idempotent повторный импорт; schema и fixtures читаются API/Python/UI. Проверки: отсутствующая выручка/маркер/регион, неизвестные значения, повтор id.

## A2 — связи и хранение документов

Типизированные рёбра payer→beneficiary (сумма/число/период, если дан) и общие физлица. Не объявлять их собственниками/поставщиками без фактов. Добавить хранение документов/chunks/даты/hash/locator совместно с Павлом, разделяя company scope и общедоступные источники. Миграции только новые, существующие не переписывать.

Готовность: изолированный профиль и объяснимые связи; ссылки на исходные поля/документы разрешаются, отсутствие периода отражено явно.

## A3 — интеграция и инфраструктура

Помочь Денису с Compose, seed и CI после A1/A2. Сбор должен сохранять материалы при недоступной модели. Hash дубли не должны уничтожать сведения о разных первоисточниках. Разобрать настоящий RSS с Павлом отдельным PR.
