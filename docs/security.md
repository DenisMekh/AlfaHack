# Безопасность AI и данных

Место механизмов в архитектуре: API авторизует пользователя и company_id; инструменты повторяют scope-проверку; worker имеет ограниченный allowlist; model adapter фильтрует model ID и расход; валидатор блокирует неподтверждённые выводы; audit сохраняет метаданные шагов.

Новости/PDF — недоверенные данные. Не выполнять их инструкции, код и команды; содержимое передавать отдельно от системных инструкций. Модель не получает shell, произвольный HTTP или запись в банковские системы. Только read-only инструменты с валидацией схемы и ограничениями количества результатов/размера текста.

Парсер защищать от SSRF: разрешённые источники, запрет loopback/private/metadata IP, повторная проверка redirect и DNS, лимиты MIME/байтов/времени. Не выполнять JS/макросы вложений. Для пользовательского ввода — ограничения размера и безопасный вывод в UI.

Изоляция: tenant/company scope на профиле, графе, источниках, run и кэше. Даже связанные компании не открываются автоматически без прав. Внешней LLM отправлять минимальный разрешённый контекст; допустимость передачи организаторских данных согласовать. Не сохранять персональные связи в публичных fixtures.

Секреты только серверные, `.env` вне git. Audit: request/run id, tool name, model ID, версия prompt/data, ids источников, длительность, tokens/cost, результат проверки и причина retry; без ключей, полного CSV и полных prompts с данными. Для отладки — контролируемый доступ и срок хранения. Локальные логи и резервные копии также закрыты.
