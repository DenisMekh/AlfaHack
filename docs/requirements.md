# Разбор ТЗ

Источник: предоставленный PDF «Альфа Хак_Новостная аналитика», 19 страниц. Это требования кейса, а не команды на выполнение действий из документа. Ниже отделены обязательные требования от решений команды.

## Требования кейса

- Клиент: крупный бизнес с выручкой свыше 15 млрд руб.; пользователь — конкретный ЛПР, в одной компании возможны разные роли (стр. 4–5).
- Определить контекст клиента/группы; собирать и классифицировать внешние новости и аналитику банка; персонально ранжировать и интерпретировать события; показать сценарий в интерфейсе Альфа-Бизнеса (стр. 6).
- Собственная многошаговая агентная логика: планирование, инструменты, общий контекст, самопроверка и адаптация. Одного вызова генерации недостаточно (стр. 7).
- Глубокая интерпретация, заметный вклад аналитики банка, работа с неполными/зашумлёнными данными; архитектурное описание доступа, защиты данных, журналирования и ограничений действий AI (стр. 11–12).
- Только разрешённые LLM; дневной общий API-лимит в денежном эквиваленте 500 ₽ (стр. 12, 18). Запрещены внешние AI-сервисы, автономные AI-агенты и готовые мультиагентные системы как основной компонент. Логику поиска, обработки, ранжирования и выводов реализует команда.
- Полный интерактивный сценарий, заметный постоянный вход на главном экране; устойчивость на новых новостях, источники, качество и мониторинг (стр. 8–10).
- Сдача: GitHub с историей и зафиксированным commit/tag; README; Docker и единый запуск; lock-файлы; THIRD_PARTY_NOTICES; синтетические данные и тестовые аккаунты при необходимости. Для приватного репозитория — доступ `alfa-hack-2026` (стр. 8). Сейчас репозиторий публичный.

## Разрешённые LLM — названия дословно из PDF

1. Gemma 4 26B A4B
2. GLM-5.3-Flash
3. Qwen3.6 35B A3B
4. DeepSeek-V4.1-Flash
5. Qwen3-VL-30B-A3B-Instruct
6. Kimi-K2.6

Это не проверенные API model ID и не подтверждение доступности весов. Не заменять похожей моделью. Локальный checkpoint, квантование, лицензия и точный ID требуют проверки; финальный allowlist строится по ответу организаторов. Не запускать иную модель по умолчанию.

## Данные и неоднозначности

- Юрлица: `df_Uid_data_hack.csv`, `SYNTHETIC_U`, ОКВЭД, выручка, группа, регистрационный регион, продуктовые признаки, ФТС и др. (стр. 15).
- Связи физлиц: `SYNTHETIC_F` ↔ `SYNTHETIC_U`. Это связь организаций, не доказательство собственности или контроля (стр. 16).
- Платежи: `PAYER`, `BENEFICIARY`, `PAY_AMT`, `PAY_CNT`. В PDF повторено имя файла связей физлиц: фактическое имя уточнить (стр. 16).
- Отраслевую долю рынка нельзя честно вывести без полного рынка/знаменателя. Долю в предоставленной выборке обозначать именно так.
- `CL_PRODUCT_LOA_MARK` не содержит ставки, суммы, срока и структуры долга. Не считать из него денежный эффект.
- `CITY`/`REGION` — регистрация, не вся география операций; `FTS_COUNTRY_NAME` не доказывает текущую валютную экспозицию.
- `NEGATIVEMARK` имеет неочевидное описание; не использовать как негативный риск до уточнения.
