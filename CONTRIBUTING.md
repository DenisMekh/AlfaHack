# Совместная работа

`main` — интеграционная ветка. Ветки: `feat/r1-…`, `feat/r2-…`, `fix/…`, `docs/…`. Один PR = одна обозримая задача. Перед работой fetch и новая ветка от `origin/main`; перед PR обновиться и разрешить конфликты своей ветки. В `main` напрямую не пушить после начальной настройки. Force push в общие ветки запрещён.

PR описывает проблему, результат, проверку и изменение контракта. Нужен один review другого участника, зелёный CI и решённые обсуждения. Каждый использует собственный GitHub-аккаунт; никаких общих токенов. Автор мержит после review либо это делает lead.

Владелец репозитория приглашает остальных через Settings → Collaborators с Write. После принятия приглашений проверяется push личной ветки. Настроить ruleset для `main`: PR, 1 approval, запрет удаления/force push; required CI включить после первого успешного запуска workflow. **Эти настройки и приглашения пока не выполнены.** CODEOWNERS заполнить реальными логинами после назначения ролей.

Публичный репозиторий не даёт всем права push. До приглашения участник может работать через fork + PR. PDF кейса, CSV организаторов, аналитика, ключи, промпты с клиентскими данными и веса моделей не коммитятся. Публикуются только синтетические fixtures с явной маркировкой.
